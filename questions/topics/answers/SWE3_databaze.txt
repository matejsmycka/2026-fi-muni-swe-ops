Databáze je uspořádaná množina dat. DBMS (databázový management systém) obstarává přístup k datům. Databáze + DBMS = databázový systém. Proč místo souborů: řeší problémy efektivity, redundance, inkonzistence, integrity a bezpečnosti; struktury dat oddělené od souborů; přístup jen přes DBMS; umožněn víceuživatelský přístup a správa oprávnění; transakce řeší inkonzistenci. Souborový systém: výhody – menší nároky, jednoduché použití. Nevýhody: obtížná konzistence, nutnost zamykání, problematické transakce.
Relační databáze je databáze organizovaná pomocí relačního modelu založeného na predikátové logice. Všechna data reprezentována n-árními relacemi. Data strukturovaná, v tabulkách. Operuje se relační algebrou. Používá jazyk SQL. Data podléhají normálovým formám. Modelování schémat pomocí UML ERD diagramu. Používá datové struktury: B+ stromy, červeno-černé stromy, R stromy.
Architektura relačních databází je postavena na relačním modelu dat = sada nástrojů pro popis dat (syntax a sémantika), vztahů mezi daty a podmínek. Skládá se z: Atribut – vlastnost objektu popsaná hodnotou s datovým typem. Doména – neprázdná množina hodnot datového typu atributu, určuje povolené hodnoty. Relace – podmnožina kartézského součinu domén, nesmí obsahovat duplicity, nezávisí na pořadí (je to množina). Relační schéma – n-tice atributů, určuje název a záhlaví tabulky. DBMS spravuje přístup k datům, transakce, souběžnost, bezpečnost.
Atribut – charakteristika/vlastnost objektu popsaná hodnotou s datovým typem. Doména – neprázdná množina hodnot datového typu atributu, určuje povolené hodnoty. Relace – podmnožina kartézského součinu domén (n-tic atributů); nesmí obsahovat duplicitní relace; nezávisí na pořadí (je to množina); prázdná relace je validní. N-tice – jeden řádek relace (jeden záznam). Tabulka – reprezentace relace v databázi.
Doména – neprázdná množina hodnot datového typu atributu. Součástí každé domény je hodnota NULL. Určuje povolené hodnoty pro daný atribut. Relační schéma – n-tice atributů; určuje název a záhlaví tabulky (kolik sloupců a jak se jmenují). Tabulka je reprezentací relace. Prázdné schéma je zakázáno. Slouží k definici struktury tabulky.
Klíč je podmnožina atributů, jejichž úlohou je jednoznačně identifikovat každou n-tici v relaci. Primární klíč – jeden zvolený kandidátský klíč. Pokud se skládá z více atributů, nazývá se kompozitní. Cizí klíč – množina atributů, která je superklíčem v jiné relaci. Vytváří vazbu mezi tabulkami a zajišťuje referenční integritu.
Superklíč – každá podmnožina atributů, která dokáže jednoznačně identifikovat každou n-tici v relaci. Kandidátský klíč – minimální superklíč (nejmenší možná podmnožina atributů jednoznačně identifikující n-tici). Primární klíč – jeden zvolený kandidátský klíč. Pokud se skládá z více atributů, je kompozitní. Cizí klíč – množina atributů, která je superklíčem v jiné relaci.
Databázové schéma je celková logická struktura databáze – definuje všechny tabulky (relační schémata), atributy, datové typy, integritní omezení, primární a cizí klíče, indexy, pohledy (views) a vztahy mezi tabulkami. Je to 'plán' databáze. Relační schéma je konkrétně definice jedné tabulky (názvy a typy sloupců).
Relační DB: data strukturovaná, v tabulkách; podléhají normálovým formám; SQL, relační algebra; B+ stromy, červeno-černé stromy; UML ERD. NoSQL: vznikly kvůli horizontálnímu škálování; dokumentové (MongoDB), key-value (Redis), grafové, XML; data nemusí mít strukturu, nepodléhají normám; CAP theorem – nelze zároveň Consistency + Availability + Partition tolerance; Eventual Consistency. NewSQL: relační DBMS s flexibilitou NoSQL pro OLTP (CockroachDB, VoltDB); Hybrid Transactional-Analytical Processing (HTAP).
Row-oriented (OLTP): klasické RDBMS (MySQL, MSSQL, Postgres, MariaDB, SQLite); vhodné pro rychlý přístup filtrovaným datům (WHERE) a INSERT. Column-oriented (OLAP): analytické databáze (DuckDB, RedShift, R dataframes, Pandas); rychlý přístup k výsledkům projekce (SELECT), přidávání sloupců; lepší komprese – používají Run-Length encoding, bitmapy.
SQL se skládá ze tří částí: DDL (Data Definition Language) – podjazyk pro definici dat, specifikace relační schémy (CREATE/ALTER/DROP TABLE, CREATE VIEW, CREATE INDEX). DML (Data Manipulation Language) – podjazyk pro manipulaci s daty (SELECT, INSERT, UPDATE, DELETE = CRUD). DCL (Data Control Language) – podjazyk pro řízení práce s daty (COMMIT, ROLLBACK, GRANT, REVOKE).
Příkaz (statement) – SELECT, UPDATE, DELETE, INSERT. Dotaz (query) – příkaz vracející relaci (SELECT). Klauzule (clause) – komponenty příkazů: WHERE, GROUP BY, FROM, HAVING. Predikát (predicate) – podmínka omezující účinky, vyhodnocená trojhodnotovou logikou (TRUE, FALSE, NULL), používá operátory: =, <, >, <=, >=, BETWEEN, LIKE, IN/NOT IN, IS/IS NOT. Výraz (expression) – konstanta nebo funkce vracející skalární hodnotu. Textové řetězce v jednoduchých uvozovkách.
Datové typy v SQL: char(n) – text s pevnou délkou. varchar(n) – text s proměnlivou délkou. int – celé číslo. real/float – reálné číslo. date, time, timestamp – časový údaj. numeric(p,s)/decimal(p,s) – číslo s pevnou délkou celé a desetinné části. Uživatelsky definované typy (např. CREATE DOMAIN v Postgres).
DDL (Data Definition Language) – podjazyk pro definici dat, specifikuje relační schéma a další objekty. Příkazy: CREATE TABLE – vytvoří novou tabulku se specifikací názvů a typů atributů. ALTER TABLE – upraví existující tabulku (ADD/DROP COLUMN nebo CONSTRAINT). DROP TABLE, DROP VIEW – vymaže tabulku/view. CREATE VIEW – vytvoří pohled (pojmenovaný SELECT, virtuální tabulka); možnost materializovaného view. CREATE INDEX – vytvoří index nad sloupcem (UNIQUE, WHERE, USING BTREE/HASH/BRIN/GIST v Postgres).
CREATE TABLE person (p_id int NOT NULL PRIMARY KEY, op char(10) UNIQUE NOT NULL, name varchar(255) NOT NULL, species varchar(255) DEFAULT 'human', j_id int FOREIGN KEY REFERENCES job_table(j_id), CHECK (p_id > 0)); Integritní omezení použitá v CREATE TABLE: NOT NULL – atribut nesmí být NULL. UNIQUE – hodnota musí být unikátní. PRIMARY KEY – definuje primární klíč. FOREIGN KEY – referenční integrita (REFERENCES). CHECK – hodnota se zkontroluje podmínkou. DEFAULT – implicitní hodnota.
DML (Data Manipulation Language) – podjazyk pro manipulaci s daty (CRUD). Příkazy: SELECT – výběr dat (projekce + selekce). INSERT – vložení záznamu (sjednocení). UPDATE – úprava záznamů (výběr + sjednocení). DELETE – odstranění záznamů (výběr). Výsledkem DML příkazů je relace. Příkazy se mohou vnořovat: SELECT FROM (SELECT FROM ...). Typicky využíváme operátory: SOME, ALL, UNIQUE, IN, NOT IN, EXISTS, NOT EXISTS.
CREATE (INSERT): INSERT INTO tabulka (sloupce) VALUES (hodnoty); odpovídá sjednocení; hodnoty musí splňovat datový typ a integritní omezení. READ (SELECT): SELECT sloupce FROM tabulka WHERE podmínka; projekce + kartézský součin + selekce; SELECT DISTINCT odstraní duplicity; AS – přejmenování. UPDATE: UPDATE tabulka SET sloupec = hodnota WHERE podmínka; odpovídá výběru a sjednocení. DELETE: DELETE FROM tabulka WHERE podmínka; odpovídá výběru.
V SQL se s transakcemi pracuje pomocí DCL: BEGIN TRANSACTION – zahájení. COMMIT – potvrzení, změny se trvale uloží. ROLLBACK – zrušení, návrat do původního stavu. Transakce je posloupnost DML příkazů převádějících databázi z jednoho konzistentního stavu do druhého. Řídí se ACID a lze nastavit úroveň izolace (SET TRANSACTION ISOLATION LEVEL).
SELECT [DISTINCT|ALL] sloupce FROM tabulka [JOIN ...] WHERE podmínka GROUP BY sloupce HAVING podmínka ORDER BY sloupce [ASC|DESC]; SELECT = projekce. FROM = kartézský součin/spojení. WHERE = selekce (predikát). GROUP BY = seskupení. HAVING = filtrování skupin. ORDER BY = řazení. Na atributy v SELECT lze aplikovat aritmetické operace. Operátory WHERE: =, <, >, <=, >=, BETWEEN, LIKE, IN, IS NULL, IS NOT NULL, AND, OR, NOT.
GROUP BY: zeskupí atributy tabulky do skupin; následně lze vybírat jen skupiny; místo WHERE se používá HAVING (filtrování skupin); pokud vynecháme GROUP BY, implikuje se každý atribut. Agregační funkce aplikované na skupiny: COUNT() – počet. AVG() – průměr. SUM() – součet. MIN() – minimum. MAX() – maximum.
NATURAL JOIN – spojení na základě stejně pojmenovaných sloupců. INNER JOIN (JOIN ... ON) – specifikujeme podmínku ON, duplicitní sloupce se přejmenují, vrátí jen řádky se shodou. OUTER JOIN: LEFT JOIN – všechny řádky z levé, NULL pro chybějící; RIGHT JOIN – všechny řádky z pravé, NULL pro chybějící; FULL JOIN – všechny řádky z obou, NULL pro chybějící. CROSS JOIN – kartézský součin.
NATURAL JOIN – automaticky na základě sloupců se společným názvem. INNER JOIN – explicitní ON, vrátí jen řádky s odpovídající hodnotou v obou tabulkách. OUTER JOIN – rozšíření NATURAL JOINu, přidává i n-tice mimo průnik: LEFT JOIN zachová levou, RIGHT JOIN zachová pravou, FULL JOIN zachová obě. Hodnoty bez shody se nahradí NULL.
Integritní omezení chrání databázi vůči náhodnému poškození a zajišťují konzistenci dat při změnách. Typy: NOT NULL – atribut nesmí být NULL. UNIQUE – hodnota musí být unikátní. PRIMARY KEY – definuje primární klíč. FOREIGN KEY – hodnota musí odpovídat klíči v jiné tabulce (referenční integrita). CHECK – hodnota se zkontroluje podmínkou. DEFAULT – implicitní hodnota. INDEX – urychluje vyhledávání. Integritu lze omezit i CREATE DOMAIN (vlastní datový typ).
Relační algebra je formální dotazovací jazyk, teoretický základ SQL. Využívá 6 základních operací: selekce, projekce, sjednocení, rozdíl, kartézský součin, přejmenování. Vstupem je jedna nebo více relací, výstupem vždy jedna relace – operace lze řetězit a vnořovat. Rozšířené operace: zobecněná projekce, agregace.
Selekce (σ): σ_predikát(R) – výsledkem je relace obsahující n-tice splňující predikát. Projekce (π): π_sloupce(R) – výsledkem je relace obsahující jen vyjmenované sloupce; mění relační schéma; duplicitní řádky odstraněny. Kartézský součin (×): R × S – výsledkem je kartézský součin dvou relací; atributy musí být disjunktní – při shodě jmen se přejmenují.
Sjednocení (∪): R ∪ S – sjednocení obou relací; musí platit stejná arita (počet atributů) a kompatibilní domény. Rozdíl (−): R − S – rozdíl dvou relací; musí platit stejná arita a kompatibilní domény. Přejmenování (ρ): ρ_X(A1,A2,...)(R) – vrátí relaci s přejmenovaným názvem X a přejmenovanými sloupci; vždy se vyjmenují všechny názvy sloupců.
Zobecněná projekce – umožňuje používat v seznamu projekce aritmetické funkce. Agregace (𝒢): 𝒢_skupina ℱ_funkce(atribut)(R) – aplikuje agregační funkci na atribut, atributy se zeskupí podle skupiny; výsledkem je relace s jednou hodnotou pro každou skupinu; agregační funkce: avg, min, max, sum, count. Všechny operace kromě count vracejí na NULL hodnotu NULL.
Transakce je posloupnost operací (DML příkazů) převádějící datovou schému z jednoho konzistentního stavu do druhého. Pracuje s databází vždy v konzistentním stavu. Během vykonávání se databáze může dostat do nekonzistentního stavu, ale na konci v konzistentním zůstane. Řídí se ACID. Implementováno pomocí tieňové databáze (shadowing).
Stavy transakce: 1) Aktivní (Active) – na začátku, během běhu. 2) Částečně potvrzená (Partially Committed) – po vykonání poslední operace. 3) Chybující (Failed) – běh nemůže pokračovat. 4) Zrušená (Aborted) – po zrušení transakce a vrácení DB do původního stavu (ROLLBACK). 5) Potvrzená (Committed) – po úspěšném dokončení (COMMIT).
ACID: Atomicity – příkazy se vykonají všechny úspěšně nebo žádné (COMMIT/ROLLBACK). Consistency – po vykonání se neporuší integritní omezení. Isolation – transakce jsou navzájem izolované, určujeme izolační úrovně. Durability – uložená data lze znovu načíst v konzistentním stavu i po výskytu chyby (výpadek, crash), zaručeno uložením na disk (WAL, shadowing).
Úrovně izolace (od nejnižší): Read Uncommitted – vidí změny okamžitě; problémy: dirty read, non-repeatable read, phantom data. Read Committed – vidí změny až po COMMIT; řeší dirty reads. Repeatable Read – zaručuje že při opakovaném SELECT nedojde k non-repeatable read; řeší dirty reads + non-repeatable read. Serializable – nejvyšší, detekuje konkurentní transakci nad stejným objektem a zruší ji (ROLLBACK); transakce běží serializovaně; řeší vše včetně phantom data. Problémy: dirty read = čtení nepotvrzených dat; non-repeatable read = dva SELECTy vrátí různé výsledky; phantom data = při opakovaném SELECT přibývají/mizí řádky.
Souběžné zpracování: databáze vytváří plán (schedule), který musí být serializovatelný. Conflict serializable: kontroluje graf závislostí čtení a zápisů; pokud neexistuje cyklus = existuje sériový plán = konzistentní stav s minimálním lockováním. View serializable: relaxuje podmínku cyklů, kontroluje pouze pořadí read-write operací na začátku, během a na konci transakcí. V plánech nás zajímají jen operace čtení a zápisu. Paralelní výpočet je rychlejší, ale může dojít k deadlocku.
Deadlock je cyklická závislost mezi paralelními transakcemi. Vzniká, když T1 čeká na zámek držený T2 a T2 čeká na zámek držený T1 – ani jedna nemůže pokračovat. Řešení: detekce deadlocku – periodická kontrola grafu závislostí a ROLLBACK jedné transakce; prevence deadlocku – timeout, získávání všech zámků najednou.
Normalizace databáze je proces organizace dat do tabulek pro odstranění redundance (duplicitní data), zabránění anomáliím při INSERT/UPDATE/DELETE a zlepšení integrity dat. Postupuje přes normálové formy (1NF → 2NF → 3NF → BCNF). Vyšší formy zpřísňují podmínky. Opakem je denormalizace – záměrná redundance pro zlepšení výkonu čtení.
1NF: všechny atributy atomické (nedělitelné), žádné opakující se skupiny, každý sloupec unikátní název. 2NF: splňuje 1NF + neexistují částečné závislosti (každý neklíčový atribut závisí na celém primárním klíči, ne jen na jeho části); relevantní pro kompozitní PK. 3NF: splňuje 2NF + neexistují tranzitivní závislosti (neklíčové atributy nejsou závislé na jiných neklíčových). BCNF: silnější než 3NF; každý determinant je kandidátským klíčem.
Indexování je proces zrychlující přístup k údajům za cenu zpomalení operací vkládání a mazání. Indexovaný sloupec má přiřazenou menší indexovací tabulku. Algoritmicky redukujeme počet diskových přístupů. Indexy: zoradené (ordered) – záznamy podle vyhledávacího klíče; hashované (hashed) – kyblíky z hashovací funkce. Nejpoužívanější struktura: B+ stromy. Data se ukládají např. v Postgres jako 8KB stránkovací soubory.
Primární index (primary/clustering): vyhledávací klíč určuje fyzické pořadí záznamu v souboru; soubory jsou podle něj fyzicky seřazeny na disku; může být jen jeden v tabulce; nemusí být PK; může být hustý i řídký. Sekundární index (secondary/non-clustering): vyhledávací klíč určuje jiné pořadí než v seřazeném souboru; může být pouze hustý.
B+ strom: víceúrovňový index (hierarchický) – vyvážený n-ární strom. Všechny datové záznamy uloženy v listech (leaf nodes). Vnitřní uzly obsahují jen klíče pro navigaci. Listy propojeny pro efektivní sekvenční průchod (range queries). Strom je výškově vyvážený – cesta ke všem listům stejná. Proč: efektivní pro bodové i rozsahové dotazy (BETWEEN, >, <); vhodný pro JOIN, WHERE; stabilní výkon i při velkém objemu dat; minimalizuje diskové přístupy.
Hashování: hashovací funkce převádí vyhledávací klíče na adresy kyblíků (buckets). Používá se při vyhledávání, přidávání a mazání. Ideální funkce je rovnoměrná – každý kyblík stejný počet záznamů. Výhody: rychlé pro přesné vyhledávání (=). Nevýhody: neefektivní pro rozsahy (WHERE x > y, BETWEEN). Problém přetečení kyblíků (overflow) a kolizí. Řešení kolizí: overflow chaining (closed hashing).
Statické hashování: hashovací funkce fixní, při růstu DB dochází k přetečení kyblíků. Dynamické hashování: funkce se mění podle velikosti DB, přizpůsobuje počet kyblíků. Kolize: různé klíče dostanou stejný kyblík; řešení – overflow chaining (closed hashing), přetékající záznamy do spojového seznamu. Cíl: minimalizovat kolize, ideálně silná bezkoliznost, rovnoměrná distribuce.
Hustý index (dense): indexový záznam pro každou hodnotu v tabulce; rovné hodnoty se neopakují; velký overhead při INSERT/DELETE; rychlejší při JOIN, WHERE. Řídký index (sparse): indexový záznam jen pro některé hodnoty; nejprve najdeme nejbližší záznam, pak sekvenčně procházíme tabulku; pomalejší ale zabírá méně místa na disku. Víceúrovňový index: když se primární nevejde do RAM, vytvoří se několik řídkých indexů.
Indexování (ordered): indexové záznamy podle hodnoty klíče; využívá B+ stromy; efektivní pro přesné vyhledávání i rozsahy (<, >, BETWEEN); univerzálnější. Hashování: kyblíky z hashovací funkce; efektivní pouze pro přesné vyhledávání (=); neefektivní pro rozsahy; rychlejší pro bodové dotazy. Hashování vhodné pro equi-joiny.
Index zrychluje operace čtení (SELECT) – rychlejší WHERE, JOIN, ORDER BY. Index zpomaluje operace zápisu (INSERT, UPDATE, DELETE) – nutnost aktualizovat indexové struktury. Čím více indexů, tím pomalejší zápis, ale potenciálně rychlejší čtení. Vhodné indexovat sloupce používané ve WHERE a JOIN. Primární index ovlivňuje fyzické uložení na disku (clustered).
Vyhodnocení SQL dotazu v krocích: 1) Parsování – syntaktická a sémantická kontrola. 2) Logický plán – převod na strom operací relační algebry. 3) Optimalizace – optimalizátor vybírá nejefektivnější fyzický plán. 4) Fyzický plán – konkrétní algoritmy, indexy, pořadí JOINů. 5) Exekuce – provedení plánu a vrácení výsledné relace.
Logický plán: abstraktní reprezentace SQL dotazu jako strom operací relační algebry (σ, π, ⋈, ×); nezávislý na fyzické implementaci. Fyzický plán: konkrétní realizační plán od optimalizátoru; obsahuje výběr algoritmů (hash join/merge join/nested loop), výběr indexů, pořadí JOINů, způsob přístupu (table scan vs index scan). Cíl: minimalizovat cenu (I/O, CPU). Optimalizátor vybírá z možných plánů ten s nejnižší odhadovanou cenou.
Indexed Nested-Loop Join: každé n-tici najde druhou pomocí indexu; vhodné pro non-equi joins (WHERE a.x > b.y); využívá existující indexy. Merge Join: relace se seřadí podle indexů a pak spojí; pro equi-join (WHERE a = b); předpokládá seřazené vstupy. Hash Join: n-tice se porovnávají pomocí kyblíků (hash); vhodné pro JOIN velkých tabulek; velký overhead (RAM); lze paralelizovat; nevyžaduje indexy.
Trigger (spouštěč): specifikuje činnosti nad tabulkou při události (INSERT, UPDATE, DELETE); volitelně WHEN (INSERTING, UPDATING, DELETING); procedura BEGIN ... END, volitelně FOR EACH ROW; použití pro zajištění integrity ve složitých DB. View (pohled): pojmenovaný SELECT uložený v DB = virtuální tabulka; materializovaný view se přepočítává při změně dat; použití pro zjednodušení dotazů, bezpečnost, abstrakci.
